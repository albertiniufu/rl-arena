estrutura · contrato de agente

Três arquivos, um contrato on-policy

O A2C usa a mesma topologia de rede do PPO, mas um fluxo de dados diferente: o rollout é consumido assim que enche (ou quando o episódio termina) e descartado depois do update.

fundamentos · ator e crítico

Um escolhe, o outro avalia

A mesma CNN alimenta duas cabeças. O ator aprende π(a|s) categórica; o crítico aprende V(s), usado para reduzir a variância da vantagem.

→Compartilhar features. Como no PPO, as duas cabeças usam o mesmo encoder. Isso acopla os dois aprendizes, mas economiza parâmetros e acelera a representação.
fundamentos · alvo n-step

Retornos n-step: olhar n passos à frente

Em vez de esperar o fim do episódio (Monte Carlo) ou usar só um passo (TD), o A2C soma até n=64 recompensas e faz bootstrap no valor do passo seguinte.

Rt = rt + γ rt+1 + … + γn−1 rt+n−1 + γn V(st+n)
para no fim do episódio: truncado faz bootstrap; terminal verdadeiro não
algs/alg_a2c/agent.py — n_step_returns
for i in range(n):
    total = 0.0; discount = 1.0
    for k in range(n_steps):
        j = i + k
        total += discount * rewards[j]
        if episode_ends[j] or terminated[j]:
            if not terminated[j]:
                total += discount * gamma * next_values[j]
            break
        if k == n_steps - 1:
            total += discount * gamma * next_values[j]
            break
        discount *= gamma
nn = batch_size. O construtor usa n_steps = batch_size quando não recebe outro valor; o CLI padrão dá 64. Não há relação com minibatches: o A2C usa o rollout inteiro de uma vez.
!Fronteira de episódio. episode_ends interrompe a soma mesmo quando o fim é truncamento, mas ainda aplica γ·V(s′). Só terminated corta o bootstrap.
CPUOnde roda. Os dois laços usam .item() por passo; em CUDA isso sincroniza. O código calcula os retornos em CPU (≈10 ms por rollout de 64) e só devolve o resultado ao device.
update · um passo de gradiente

O update inteiro em uma passada

Quando o buffer enche, o agente recalcula valores e log-probs, normaliza as vantagens e faz um único passo de Adam sobre o rollout inteiro. Depois limpa a fila.

  1. Valores V(s) e V(s′) sob no_grad; retornos n-step em CPU.
  2. Vantagem A = R − V(s), normalizada por (A−média)/desvio.
  3. Perdas: política −logπ(a|s)·A, valor MSE e bônus de entropia.
  4. Passo único com gradiente clipado em 10; steps += 1; buffer.clear().
logits, values = self.online(s)
dist = Categorical(logits=logits)
log_probs = dist.log_prob(a)
policy_loss = -(log_probs * advantages).mean()
value_loss = mse_loss(values, returns)
entropy = dist.entropy().mean()
loss = (policy_loss + value_coef * value_loss
        - entropy_coef * entropy)
→É a mesma política do PPO? Sim: categórica via softmax dos logits. A diferença é que o A2C não faz épocas nem clipping — usa o rollout uma vez.
!Gatilho por episódio. end_episode() marca a fronteira e, se o buffer não estiver vazio, atualiza na hora. Assim o rabo do episódio não fica esperando 64 passos.

integração · train, evaluate, play

Como o train.py usa o A2C

Loop

act → env.step → buffer.add → learn() a cada passo. O learn() devolve None até o buffer ter n_steps.

Fim de episódio

O train.py chama end_episode(info): o buffer marca a fronteira e, se houver transições, o update acontece imediatamente.

Fim do treino

finish_training() consome o rollout parcial que sobrou quando --max-hours ou o número de episódios termina.

# vetorizado: coleta em workers, update em lote
python train.py --arena seek_coin --alg a2c \
    --envs 8 --opponent rule --episodes 300

# sobrepor coleta (CPU) e update (GPU)
python train.py --arena seek_coin --alg a2c \
    --envs 8 --overlap --opponent rule --episodes 300
→Sem ε e sem warmup. O train.py detecta on_policy=True e não passa epsilon_min/warmup ao construtor; a exploração é a entropia e a amostragem.
!Overlap. Só PPO/A2C aceitam --overlap: uma thread coleta o próximo rollout numa cópia CPU da política enquanto a thread principal atualiza na GPU. Não é bit a bit reprodutível.

fechamento · trade-offs

Quando o A2C é a escolha certa

Ganha

Implementação curta, um gradiente por rollout e nenhum hiperparâmetro de recorte. Ótimo para depurar a infraestrutura e para ambientes onde o custo de coleta domina.

Limita

Sem clipping, passos grandes podem destruir a política; sem reuso, cada amostra é usada uma vez. Em dinâmica não estacionária (nível 2), a variância alta pode atrasar a adaptação.

→Para levar. A2C = ator categórico + crítico + retornos n-step + vantagem normalizada. O buffer é uma fila, não um replay; o update é único e o rollout é descartado.
!Próximo passo natural. O PPO (ppo-aula.html) reaproveita o mesmo rollout por várias épocas e recorta a razão de probabilidades.
