motivação · quebra da simetria

Quando os agentes não são intercambiáveis

O IPPO e o MAPPO compartilham uma política entre agentes. O HAPPO parte do cenário oposto: metade dos times só coleta, a outra metade só empurra — os espaços de ação efetivos são diferentes.

IPPO

Uma rede para todos; crítico local. Simples e amostra-eficiente quando o papel é o mesmo.

MAPPO

Ator compartilhado + crítico centralizado. A execução continua local, mas o ator ainda assume papéis simétricos.

HAPPO

Um ator por agente + crítico centralizado. O update sequencial preserva a validade da razão de política sob a nova política dos agentes anteriores.

algs/alg_happo/agent.py
class HAPPOAgent:
    algorithm = "happo"
    arch_version = "alg-happo-v1"
    on_policy = True
    multi_agent = True
    accepts_roles = True
→Por que não compartilhar? Com um ator compartilhado, atualizar o agente i muda também as razões dos agentes j que usam a mesma rede. O HAPPO elimina esse acoplamento por construção.
!Custo. N atores = N CNNs. O crítico é um só; o update é sequencial, então o tempo de treino cresce com o número de agentes.
redes · atores locais + crítico centralizado

Atores locais, crítico com visão global

Cada ator vê só a própria observação. O crítico vê as features de todos os agentes no mesmo passo mais um one-hot de quem está sendo avaliado — e só existe no treino (CTDE).

Ator i

CNN do repo → 1280 features → MLP 128 → logits. Parâmetros independentes por agente. Na execução, só ele é necessário.

Crítico centralizado

Uma CNN compartilhada entre as linhas extrai as features de cada agente. A MLP final recebe n_agents × 1280 + n_agents (features conjuntas + one-hot) e devolve um V por agente.

→Por que um V por agente? Cada agente tem o seu retorno e a sua vantagem; o crítico centralizado só compartilha a representação do estado conjunto. O GAE é calculado por agente.

update · o coração do HAPPO

Atualizar em ordem, corrigindo a razão

Para o agente i, a razão de política é multiplicada pelo produto acumulado das razões dos agentes já atualizados. Esse fator corrige a vantagem conjunta decomposta sob a nova política dos anteriores.

Mi = Πj<i πj,novo(aj|oj) / πj,velho(aj|oj)
razão usada = [πi,novo(ai|oi) / πi,velho(ai|oi)] · Mi
  1. Congela log-probs antigos por agente (em blocos de eval_chunk_steps=64).
  2. GAE por agente com os valores centralizados e vantagens normalizadas no conjunto.
  3. Crítico primeiro: epochs de minibatches contra os retornos do GAE.
  4. Atores em ordem: para cada i, epochs de minibatches com ratio × ratio_pre; depois recalcula a razão do agente i e a acumula em ratio_pre, sem gradiente.
!Ordem importa. O ratio_pre é zerado no começo de cada update e atualizado após cada ator. Os agentes anteriores já estão congelados naquele momento, por isso o recálculo pode ser no_grad.
papéis · coletores e empurradores

Máscaras de ação por papel

O cenário do seek_coin declara papéis. Coletores não podem empurrar: as ações PUSH_LEFT/PUSH_RIGHT recebem logit −1e9 antes da categórica, então nunca são amostradas nem entram na perda.

masks = torch.ones(n_agents, n_actions, dtype=bool)
for i, role in enumerate(self.agent_roles):
    if role == COLLECTOR_ROLE:
        masks[i, PUSH_LEFT] = False
        masks[i, PUSH_RIGHT] = False

def _masked_logits(self, logits, agent_index):
    if not self._has_action_mask:
        return logits
    return logits.masked_fill(
        ~self.action_masks[agent_index], -1e9)
→Defesa em profundidade. O ambiente também converte empurrões de coletores em STOP, caso uma ação inválida chegue por outro caminho.
!Papéis no construtor. agent_roles é opcional; sem ele, todas as ações são permitidas e o HAPPO se comporta como um MAPPO com atores separados. ArenaConfig.agent_roles agora é preenchido pela CLI: --scenario collectors-vs-pushers --teams K (time par) monta o cenário, grava os papéis no checkpoint e passa agent_roles ao HAPPO; evaluate.py/play.py reconstroem os papéis da config.
−Máscara só no ator. O crítico continua vendo o estado conjunto inteiro; a máscara não reduz a observação, só a política.
memória · buffer indexado por passo

Um registro por passo conjunto

O buffer guarda as transições de todos os agentes no mesmo passo, como no MAPPO. O update usa matrizes (T, n_agents) para recompensa, valor, terminal e fim de episódio.

alg_happo/rollout_buffer.py
# add_transition(i, s, a, r, ns, terminated)
# acumula por agente até todos contribuírem
# e então fecha o passo conjunto
self.buffer.add(agent_index, state, action, reward,
                next_state, terminated, log_prob)

# as_arrays() → dict com
# states (T, N, C, H, W), actions (T, N),
# rewards (T, N), terminated (T, N), ...
→Por que não um buffer por agente? O crítico centralizado precisa das observações de todos no mesmo instante. O rollout é commitado só quando todos os agentes escreveram no passo.
!Coleta. Todos os agentes decidem uma vez por env.step; a ação é mantida nos frame_skip substeps. O end_episode marca a fronteira para todos.

# todos contra todos, 4 agentes
python train.py --arena seek_coin --alg happo \
    --agents 4 --scenario all-vs-all \
    --checkpoint-dir checkpoints/happo4

# dois times de dois
python train.py --arena seek_coin --alg happo \
    --agents 4 --scenario teams --teams 2 \
    --checkpoint-dir checkpoints/happo_teams

# times mistos: 1 coletor + 1 empurrador por time
python train.py --arena seek_coin --alg happo \
    --agents 4 --scenario collectors-vs-pushers --teams 2 \
    --checkpoint-dir checkpoints/happo_roles

# espectador e duelo
python play.py --arena seek_coin \
    --checkpoint checkpoints/happo_teams/best.pt

    --ppo-checkpoint ... --happo-checkpoint ...
→Mesmo ambiente. Com multi_agent=True, o train.py monta um Scenario e usa ArenaMultiEnv; o cenário vai para a config e não pode mudar na retomada.

fechamento · trade-offs

Quando vale o HAPPO

Ganha

Papéis diferentes cabem em atores diferentes, sem forçar uma política compartilhada a representar comportamentos conflitantes. O update sequencial mantém a teoria do trust region multiagente.

Limita

N atores e update sequencial: mais parâmetros, mais tempo e mais memória. Sem papéis configurados, boa parte da vantagem sobre o MAPPO desaparece.

→Para levar. HAPPO = atores independentes + crítico centralizado + atualização sequencial com M_i = Π_{j<i} razão_j. A máscara de papel é uma camada extra, não o núcleo.
!Compare com IPPO/MAPPO (ippo-aula.html, mappo-aula.html) no mesmo cenário e seed. Se não há papéis, o HAPPO tende a pagar o custo sem o benefício.
