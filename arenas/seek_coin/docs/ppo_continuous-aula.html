fundamentos · política

A política é uma Gaussiana por dimensão

O ator devolve a média de cada dimensão. O desvio é um parâmetro global por dimensão — não uma saída da rede — limitado a [e−5, e2] para manter a exploração estável.

a ~ N(μθ(s), diag(σ²))    σ = exp(log_std),  log_std ∈ [−5, 2]
ausada = clip(a, low, high)    sem correção de densidade
def forward(self, x):
    feats = self.features(x)
    mean = self.actor_mean(feats)
    log_std = self.actor_log_std.clamp(-5.0, 2.0).expand_as(mean)
    value = self.critic(feats).squeeze(-1)
    return mean, log_std, value

# amostragem de treino
action = mean + log_std.exp() * torch.randn_like(mean)
action = self._clamp(action)
σDesvio global. Um único vetor de parâmetros actor_log_std (dimensão da ação) é aprendido; ele não depende do estado. É simples e barato — e limita a política a uma forma de exploração homogênea no espaço.
!Clamp ≠ squash. Recortar a ação nos limites muda a distribuição efetiva, mas o log-prob usado no PPO é o da Gaussiana original. É uma aproximação didática: fora dos limites a densidade não é corrigida.
−Guloso. act(..., greedy=True) devolve a média (recortada), sem ruído. É o que evaluate.py/play.py usam.
fundamentos · densidade conjunta

Log-prob e entropia somam as dimensões

Como as dimensões são independentes (diagonal), a densidade conjunta é o produto das marginais: em log, a soma. A razão do PPO e o bônus de entropia usam essa soma.

log π(a|s) = Σd log N(ad; μd, σd²)
H[π] = Σd ½·log(2πe·σd²)
dist = Normal(mean, log_std.exp())
old_log_probs = dist.log_prob(a).sum(dim=1)
...
log_probs = dist.log_prob(a[idx]).sum(dim=1)
ratio = torch.exp(log_probs - old_log_probs[idx])
entropy = dist.entropy().sum(dim=1).mean()
→Mesmo recorte. A perda de política é idêntica à do PPO discreto, só que a razão vem de densidades gaussianas. ratio = π_novo(a|s) / π_velho(a|s).
!Entropia desligada. O default é entropy_coef=0.0: a Gaussiana já explora pelo σ aprendido. Ligar entropia empurra σ para cima e pode impedir a convergência fina.
update · o mesmo PPO

O update é o PPO de sempre

  1. Rollout de 1024 transições (estado, ação contínua, recompensa, próximo estado, terminal).
  2. GAE(λ) com compute_gae importado do alg_ppo; vantagens normalizadas.
  3. 10 épocas de minibatches (64), recorte em 1±0,2, perda de valor 0,5 e sem entropia.
  4. Passo do Adam com lr=3e-4 e gradiente clipado em norma 0,5; rollout descartado ao final.
unclipped = ratio * adv
clipped = torch.clamp(ratio, 1.0 - self.clip,
                      1.0 + self.clip) * adv
policy_loss = -torch.min(unclipped, clipped).mean()
value_loss = mse_loss(values, returns[idx])
loss = policy_loss + value_coef * value_loss
→Checkpoint igual. evaluate.py/play.py leem o algoritmo do checkpoint e chamam set_action_bounds a partir do Box reconstruído da config.
!Sem minibatch de observação? O buffer guarda observações (N,) no vector encoder; o agente é agnóstico à forma do estado, como todos os outros.
aplicação · arena economy

Onde o PPO contínuo roda no repo

A arena economy tem duas visões: o banco-agente e o governo. Ambas usam ações contínuas limitadas e observações vetoriais — o caso de uso do ppo_continuous.

BankEnv — banco-agente

3 × n_groups ações: taxa de aprovação [0; 1], limite [0,1; 1] e spread [0; 0,25] por grupo de risco. Observação de 5 + 6n + 3 dimensões.

EconomyEnv — governo

3 ações: imposto de renda [0; 0,60], razão de gastos [0,05; 0,50] e taxa de juros [0; 0,05]. Observação de 11 dimensões.

# da raiz do repo
python train.py --arena economy \
    --alg ppo_continuous --episodes 200

python evaluate.py --arena economy \
    --checkpoint checkpoints/economy/best.pt

python play.py --arena economy \
    --checkpoint checkpoints/economy/best.pt
→Por que não DQN? As ações são proporções contínuas (taxa, limite, spread). Discretizá-las perderia resolução e criaria uma explosão combinatória com n_groups.
!Limites por dimensão. O Box do ambiente define low/high por dimensão; o agente recorta o vetor amostrado nesses limites, sem normalizar para [−1,1].

limitações · honestidade do desenho

O que este PPO contínuo não faz

Sem squashing

Muitos PPOs contínuos usam tanh e corrigem o log-prob pela derivada do squash. Aqui só há clip: a ação fica dentro do Box, mas a densidade usada no PPO não corresponde à densidade efetiva perto da borda.

σ não depende do estado

Um log_std global por dimensão é fácil de treinar e estável, mas não modela “mais incerteza em alguns estados”. Para os controles macro da economy, é um compromisso razoável.

!Consequência prática. Se o treino colapsar em ações nos extremos do Box, o gradiente pode ficar enganoso: a política “acha” que amostrou o valor original. Aumentar o horizonte do GAE ou reduzir o lr costuma estabilizar.
