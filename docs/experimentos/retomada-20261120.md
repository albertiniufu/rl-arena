## 3. Como retomar (depois do reboot)

Atalho: tudo o que está nesta seção, na ordem, está no script
[`scripts/retomar_experimentos.sh`](../../scripts/retomar_experimentos.sh)
(idempotente; `--status` só inspeciona, `--force` ignora o aviso de memória):

```bash
cd /home/albertini@win.ufu.br/rl-arena
sudo pkill -f rpcd_lsad            # passo manual (root)
scripts/retomar_experimentos.sh    # sobe a Fila, despausa e dá retry
```

Passo a passo equivalente, se preferir rodar na mão:

1. Liberar a memória (seção 1) e conferir `free -h`.
2. Subir o servidor da Fila (ele **não** sobe sozinho no boot):

   ```bash
   cd /home/albertini@win.ufu.br/rl-arena
   /home/albertini@win.ufu.br/venvs/main/bin/python - <<'PY'
   from arenas.common.job_queue_client import ensure_server, health
   ensure_server(state="experiments/queue/queue.json",
                 logs_dir="experiments/queue/logs")
   print("health:", health())
   PY
   ```

3. Conferir o estado (deve vir `paused: true`) e despausar:

   ```bash
   curl -s http://127.0.0.1:8765/api/state | python -m json.tool | head -20
   curl -s -X POST http://127.0.0.1:8765/api/queue/resume
   ```

4. Retomar o job do nível 3 (**mesmo id**, para preservar a dependência do
   nível 4):

   ```bash
   curl -s -X POST http://127.0.0.1:8765/api/jobs/job-20261120-183301-9e4e70/retry
   ```

   O runner pula automaticamente as rodadas com `DONE` (loga `[skip]`) e
   continua com `[run]` da próxima pendente.

5. Acompanhar:

   ```bash
   tail -f experiments/queue/logs/job-20261120-183301-9e4e70.log
   # e o treino corrente em:
   tail -f experiments/EXP-20261120-ppo-vs-eppo-level3-10seeds/seed-<seed>/<alg>/train.log
   ```

6. Se algo falhar de novo, o caminho de retomada é o mesmo: `retry` no job.
   O estado da Fila fica em `experiments/queue/queue.json` (há um
   `queue.json.bak` ao lado).

## 4. Não repetir

- Não rodar `train.py` direto no terminal para treino longo: ele registra um
  job local e espera a permissão da Fila (`RL_ARENA_QUEUE_BYPASS=1` só para
  smoke tests curtos).
- Não rodar dois treinos ao mesmo tempo — a Fila é `max_parallel=1` de
  propósito (dois treinos juntos já causaram um desvio de protocolo neste
  mesmo experimento).
- Antes de retomar, `pgrep -c rpcd_lsad` deve ser 0; senão o OOM-kill volta.
